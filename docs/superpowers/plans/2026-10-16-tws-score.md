# TWS Score Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PWA para o casal avaliar cafés e restaurantes, com nota surpresa garantida no banco.

**Architecture:** SPA React + Vite servida como PWA. Supabase (projeto compartilhado `leolmgqlucuvjwquzmkl`) fornece Auth por link mágico, Postgres com RLS e Storage. Toda regra de acesso e a nota surpresa vivem em políticas RLS; o cliente só faz a camada de dados (`src/data`), lógica pura (`src/lib`) e telas.

**Tech Stack:** React 19, Vite, TypeScript, React Router 7 (`react-router`), `@supabase/supabase-js@2`, Leaflet + `react-leaflet@5`, `lucide-react`, `browser-image-compression`, `vite-plugin-pwa` + `@vite-pwa/assets-generator`, `@fontsource-variable/fraunces`, `@fontsource-variable/inter`, Vitest + Testing Library + jsdom.

**Spec:** `docs/superpowers/specs/2026-10-16-tws-score-design.md`

## Global Constraints

- Commits pequenos, um por etapa, Conventional Commits em português, **sem** trailer `Co-Authored-By` nem linha "Generated with".
- Nunca alterar objetos do outro app no projeto Supabase (`profiles`, `categories`, `transactions`, `bills`) nem `auth.users`. Tudo do app usa prefixo `tws_` e bucket `tws-photos`.
- Migrações: arquivo em `supabase/migrations/` **e** aplicado com a tool MCP `apply_migration` (project_id `leolmgqlucuvjwquzmkl`), mesmo nome.
- Colunas do banco em português snake_case; tipos TS espelham em camelCase (`notaGeral`, `visitadoEm`). Funções e componentes em inglês.
- Textos da interface em português, curtos e gentis, sem jargão técnico.
- Notas são inteiros 1–5. Média do casal = média das duas `nota_geral`, arredondada a 1 casa decimal, exibida com vírgula (`4,5`).
- Fotos: lado maior ≤ 1600px, JPEG qualidade 0.8.
- Tokens de cor (CSS custom properties em `src/styles/tokens.css`):
  - claro: `--bg #FAF7F2`, `--surface #FFFFFF`, `--text #2E2A27`, `--text-muted #6F6760`, `--accent #A0544C`, `--accent-soft #F5E8E4`, `--border #EAE3D9`
  - escuro (`prefers-color-scheme: dark`): `--bg #1C1917`, `--surface #262220`, `--text #F2ECE6`, `--text-muted #A89F97`, `--accent #D98E84`, `--accent-soft #3A2B28`, `--border #3A3431`
  - `--radius 18px`, `--font-display 'Fraunces Variable'`, `--font-body 'Inter Variable'`
- Animações ≤ 250ms, exceto a revelação (≤ 600ms). Tudo desligado sob `prefers-reduced-motion: reduce`.
- Sem gradientes, contadores, gamificação.

## Review Focus

1. **Reenvio após falha parcial** (lugar criado, avaliação falhou por rede): tentar de novo não pode criar um segundo lugar. Teste em Task 9 (`submitVisit` reaproveita `draft.placeId`).
2. **Duplo envio da mesma avaliação** (toque duplo, ou timeout após sucesso): o erro de unicidade `23505` conta como sucesso. Teste em Task 9.
3. **Usuário do outro app loga no TWS Score**: não lê nem grava nada e vê "acesso restrito". Teste SQL em Task 2 e teste de componente em Task 5.
4. **GPS negado ou endereço não encontrado**: o lugar é salvo sem `lat/lng` e o mapa ignora. Teste em Task 9 (`submitVisit` com localização nula) e Task 12 (`placesWithLocation`).
5. **Arquivo que não é imagem ou imagem que falha ao comprimir** (ex.: HEIC não suportado): mensagem gentil, o restante do envio continua. Teste em Task 7.
